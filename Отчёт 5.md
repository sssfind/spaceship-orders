# Отчёт 5. Алерты и Alertmanager

Задание: продумать алерты для Spaceship Orders, написать не меньше двух правил на метрики сервиса и 1–2 на рантайм (аналог actuator Spring/Python), приложить конфиг vmalert/Alertmanager и показать уведомление о срабатывании.

Код приложения не менялся. Метрики и `DEMO_FAULT` уже были в ДЗ 4. Новое — оценка правил (**vmalert**) и доставка уведомлений (**Alertmanager**). VictoriaMetrics по-прежнему только хранит ряды.

Стек: minikube, namespace `monitoring`. Релиз `helm upgrade --install vmalert vm/victoria-metrics-alert -f deploy/k8s/monitoring/vmalert-values.yaml`. Конфиг правил и AM — в этом файле.

Цепочка: поды `:9090` → VM `:8428` → vmalert (каждые 15s) → Alertmanager `:9093` → webhook.site.

---

## Какие алерты и почему

Окна **5m** и `for: 1m` — не 7-дневный SLO из отчёта 4, а paging: на скринкасте 7d не успеет загореться. Пороги выше error budget 1%, чтобы редкие 400/неверный пароль не пейджили.

| Алерт | Тип | Условие | Зачем |
|-------|-----|---------|--------|
| `OrderCreateErrorRate` | сервис | доля fail create за 5m **> 5%**, `for: 1m` | Главный путь пользователя; прямой burn SLO-1 |
| `IAMLoginErrorRate` | сервис | доля `iam_logins_total{result="fail"}` **> 20%**, `for: 1m` | Без входа нельзя оформить заказ (SLO-2). На скринкасте не жгли: двух сервисных достаточно |
| `HTTPHighErrorRate` | сервис | доля HTTP 5xx за 5m **> 5%**, `for: 1m` | Общая доступность API/UI (SLO-3), не только create |
| `GoGoroutinesHigh` | рантайм | `go_goroutines{namespace="spaceship"} > 20`, `for: 1m` | Аналог `jvm.threads` / actuator. Leading indicator до массовых 5xx |
| `ProcessRSSHigh` | рантайм | RSS **> 200Mi**, `for: 2m` | Аналог `jvm.memory` / `process.rss`. На стенде не стрелял — памяти мало |

Рантайм отдаёт стандартный коллектор `promhttp.Handler()` (`go_*`, `process_*`), отдельный exporter не нужен. Лейбл `namespace` ставит scrape в `vm-single-values.yaml`. Job при pod-scrape — `kubernetes-pods`, не `order-service`.

**Порог горутин.** В файле сначала было `> 50` и `for: 2m`. Живые поды держат **~8–34** горутин (vmui) — это нормальный Go (HTTP + pgx + метрики), снижать их в коде незачем. Для демо порог временно **> 20**, `for: 1m`, иначе правило вечно inactive. В отчёте: на проде ориентир сотни горутин; 20 — только чтобы показать пайплайн.

## Конфигурация

Файл: `deploy/k8s/monitoring/vmalert-values.yaml`.

- **vmalert:** `datasource` → `vm-single-victoria-metrics-single-server.monitoring.svc:8428` (не 8429 и не Victoria Logs `:9428`). `notifier` → Alertmanager того же релиза `:9093`.
- **Правила** — Prometheus-совместимый YAML в `server.config.alerts.groups`.
- **Alertmanager:** `receiver: webhook`, `group_by: [alertname]`, `group_wait: 10s` (на стенде быстрее дефолтных 30s), `repeat_interval: 1h`, `send_resolved: true`. Почту не использовали: SMTP на minikube неудобен.

Сервисы VM и vmalert **headless** (`ClusterIP: None`). Port-forward надёжнее на под/deploy:

```bash
kubectl -n monitoring port-forward pod/vm-single-victoria-metrics-single-server-0 8428:8428
kubectl -n monitoring port-forward deploy/vmalert-victoria-metrics-alert-server 8880:8880
kubectl -n monitoring port-forward svc/vmalert-victoria-metrics-alert-alertmanager 9093:9093
```

UI: vmui http://localhost:8428/vmui · vmalert http://localhost:8880 · AM http://localhost:9093  
Если браузер `ERR_CONNECTION_REFUSED` — туннель не запущен или терминал закрыт, это не падение VM.

## Как срабатывали

Состояния vmalert: **inactive** → **pending** (условие есть, `for` ещё нет) → **firing** (ушло в AM и на webhook).

### Сервис (скрин vmalert Groups / Alerts)

```bash
kubectl -n spaceship set env deploy/order DEMO_FAULT=create_fail
kubectl -n spaceship rollout status deploy/order
# UI: minikube service order -n spaceship --url  — порт приложения, не :9090
# несколько CreateOrder, подождать 1–2 минуты (rate и два scrape)
```

Загорелись `OrderCreateErrorRate` (value = 1, все create — ошибки) и `HTTPHighErrorRate` (~0.46–0.66: часть запросов UI всё ещё 200). После `DEMO_FAULT=off` за ~5m окна оба стали inactive.

`IAMLoginErrorRate` остался inactive: не включали `login_fail` на IAM.

### Рантайм

После снижения порога до 20: `GoGoroutinesHigh` pending, затем firing, value **22**, под `order-…`.

### Уведомление (обязательный артефакт ДЗ)

Alertmanager: группа `alertname="GoGoroutinesHigh"`, receiver `webhook`.  
webhook.site: `POST`, `user-agent: Alertmanager/0.34.1`, JSON `"status": "firing"`, `"alertname": "GoGoroutinesHigh"`, annotation «Много горутин у order-…», `22 goroutines`.

Смотреть **POST** в Inbox, не GET самой страницы.
