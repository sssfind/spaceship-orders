# Отчёт 4. SLI, SLO и SLA

## Выбранные метрики

Три индикатора построены на метриках Order и IAM, которые отдаются в Open Metrics с отдельного порта `:9090` (`METRICS_HOST` / `METRICS_PORT`). VictoriaMetrics забирает их по аннотациям `prometheus.io/*`. Синтетический пробер — blackbox-exporter (`deploy/k8s/blackbox.yaml`).

| # | Метрика | Где пишется | Зачем как SLI |
|---|---------|-------------|----------------|
| 1 | `orders_created_total`, `orders_create_failed_total{reason}` | `order/internal/service/order/create.go` | Доля успешных созданий заказа (RBSLO) |
| 2 | `iam_logins_total{result="ok\|fail"}` | `iam/internal/service/auth/service.go` | Доля успешных логинов (RBSLO) |
| 3 | `http_requests_total{service,method,code}` | `platform/pkg/logger/http.go` → `platform/pkg/metrics` | Доля хороших минут HTTP (TBSLO) |

Дополнительно для демонстрации:

- `http_request_duration_seconds` — латентность (режим `DEMO_FAULT=slow`);
- `probe_success` — blackbox GET `/health` у Order и IAM;
- `orders_paid_total`, `orders_pay_failed_total`, `orders_cancelled_total`, `orders_revenue_total`.

Выручка в SLI не входит: это бизнес-объём, а не доступность.

Запросы для vmui лежат в `deploy/k8s/monitoring/sli-queries.promql`. На скринкасте окно **1h**, в формулировке SLO — **7 дней**.

## SLI, SLO и SLA

### SLI-1. Успешность создания заказа (RBSLO)

Доля успешных операций создания заказа:

```
SLI_create = rate(orders_created_total[W])
           / (rate(orders_created_total[W]) + rate(orders_create_failed_total[W]))
```

**SLO-1.** `SLI_create ≥ 99%` за скользящие 7 дней. Error budget: 1%.

### SLI-2. Успешность логина (RBSLO)

```
SLI_login = rate(iam_logins_total{result="ok"}[W])
          / rate(iam_logins_total[W])
```

**SLO-2.** `SLI_login ≥ 99%` за скользящие 7 дней.

### SLI-3. Доступность HTTP (TBSLO)

Минута хорошая, если доля ответов без 5xx за эту минуту не ниже 99%:

```
good_minute = (rate(http_requests_total{code!~"5.."}[1m])
            / rate(http_requests_total[1m])) >= 0.99

SLI_avail = avg_over_time(good_minute[W:1m])
```

**SLO-3.** `SLI_avail ≥ 99%` за скользящие 7 дней.

Пробер `/health` считается отдельно:

```
SLI_probe = avg_over_time((probe_success == 1)[W:1m])
```

### SLA приложения

Пользователь Spaceship Orders в течение календарного месяца может регистрироваться, входить и оформлять заказы с доступностью **не ниже 99%**.

**Общий SLA** — логическое И: нарушено любое из SLO-1…SLO-3 ⇒ SLA нарушен. На графике:

```
SLA = ( (SLI_create >= 0.99) + (SLI_login >= 0.99) + (SLI_avail >= 0.99) ) / 3
```

Значение `1` — все цели выполнены, ниже — хотя бы одно SLO красное.

Последствия для учебного стенда: фиксация инцидента и разбор, без денежных компенсаций.

## Изменения приложения для скринкаста

1. **Отдельный порт метрик** у Order и IAM (`platform/pkg/metrics.NewServer`, по умолчанию `:9090`). С основного HTTP `/metrics` снят.
2. **Счётчики SLI** при создании/оплате/отмене заказа и при логине/регистрации.
3. **HTTP RED-метрики** в middleware логгера (без `/health` и `/metrics`).
4. **`DEMO_FAULT`** (`off` / `create_fail` / `login_fail` / `slow`):
   - `create_fail` — ~50% `CreateOrder` возвращают 500 (`ErrInjectedFailure`);
   - `login_fail` — все логины отклоняются;
   - `slow` — `PayOrder` спит 2 секунды (растёт p95).
5. **Blackbox-exporter** в namespace `spaceship` плюс scrape-job `blackbox-health` в `deploy/k8s/monitoring/vm-single-values.yaml`.
6. **postgres-exporter** sidecar у `orders-db` и `iam-db`.

Переключение для демо (после сборки образа):

```bash
kubectl -n spaceship set env deploy/order DEMO_FAULT=create_fail
# нагрузка через UI или curl POST /api/v1/orders
kubectl -n spaceship set env deploy/iam DEMO_FAULT=login_fail
kubectl -n spaceship set env deploy/order DEMO_FAULT=slow
kubectl -n spaceship set env deploy/order DEMO_FAULT=off
kubectl -n spaceship set env deploy/iam DEMO_FAULT=off
# TBSLO пробера: kubectl -n spaceship scale deploy/order --replicas=0
```

vmui VictoriaMetrics (не Logs):

```bash
kubectl -n monitoring port-forward svc/vm-single-victoria-metrics-single-server 8428:8428
```

Открыть `http://localhost:8428/vmui`, вставить запросы из `sli-queries.promql`, наложить `vector(0.99)`.
