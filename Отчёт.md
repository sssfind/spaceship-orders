## Стек

- Язык и сервисы: Go 1.26, HTTP (chi + ogen), два микросервиса — Order и IAM
- БД: PostgreSQL 17 (отдельные инстансы orders-db и iam-db)
- Оркестрация: minikube + Kubernetes-манифесты в deploy/k8s
- TSDB: VictoriaMetrics Single (чарт vm/victoria-metrics-single)
- Модель экспорта: Pull, формат OpenMetrics/Prometheus, путь /metrics
- Service discovery: Kubernetes SD (role: pod) по аннотациям prometheus.io/*

VictoriaMetrics установлена в namespace monitoring:

```bash
helm install vm-single vm/victoria-metrics-single \
  -n monitoring --create-namespace \
  -f deploy/k8s/monitoring/vm-single-values.yaml
```

UI таргетов: http://localhost:8428/targets (после `kubectl port-forward` на под vmsingle).

## Экспортеры
### 1. Встраиваемый экспортер рантайма Go
Библиотека `github.com/prometheus/client_golang`, обработчик `promhttp.Handler()`.
Из коробки отдаёт метрики рантайма: `go_goroutines`, `go_memstats_*`, `process_cpu_seconds_total`, `process_resident_memory_bytes` и остальные `go_*` / `process_*`.
HTTP-сервер метрик слушает отдельный внутренний порт **9090** (`METRICS_HOST` / `METRICS_PORT`). В Service / NodePort этот порт не публикуется — scrape только изнутри кластера. Основной API остаётся на 8081 (Order) и 8082 (IAM).
Файлы: `order/internal/app/app.go`, `iam/internal/app/app.go`.
### 2. Собственные бизнес-метрики
Те же клиентские библиотеки Prometheus (`promauto`: Counter, CounterVec, Histogram) в пакетах `order/internal/metrics` и `iam/internal/metrics`. Инкремент в сервисном слое после операции.
### 3. Внешний экспортер PostgreSQL
Sidecar `quay.io/prometheuscommunity/postgres-exporter:v0.17.1` в подах `orders-db` и `iam-db`. Контейнеры одного пода делят сеть, exporter ходит в БД по `localhost:5432`, метрики отдаёт на порту *9187*.
Проверочная метрика — `pg_up == 1`. Также есть `pg_stat_database_*`, `pg_stat_activity_count` и другие `pg_*`.
Манифесты: `deploy/k8s/orders-db.yaml`, `deploy/k8s/iam-db.yaml`.

### Service discovery
На pod template деплойментов повешены аннотации:
```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "9090"   # приложения; у postgres-exporter "9187"
prometheus.io/path: "/metrics"
```

Конфиг scrape: `deploy/k8s/monitoring/vm-single-values.yaml`, job `kubernetes-pods`. Init-контейнеры отбрасываются, порт цели сверяется с аннотацией (`keep_if_equal`), чтобы у пода Postgres не скрейпился 5432

## Бизнес-метрики

### Order
| Метрика | Тип | Смысл | Где |
|---|---|---|---|
| `orders_created_total` | Counter | Число успешно созданных заказов | `CreateOrder` |
| `orders_paid_total{payment_method}` | Counter | Число успешных оплат | `PayOrder` |
| `orders_cancelled_total` | Counter | Число отменённых заказов | `CancelOrder` |
| `orders_revenue_total{payment_method}` | Counter | Суммарная выручка по оплаченным заказам | `PayOrder` |
| `order_total_price` | Histogram | Распределение суммы заказа при создании | `CreateOrder` |
| `orders_create_failed_total{reason}` | Counter | Неуспешные попытки создания (`empty_parts`, `part_not_found`, `insufficient_stock`, `repository_error`) | `CreateOrder` |
Выручка считается при оплате, а не при создании: иначе отменённые заказы попадали бы в revenue.
### IAM
| Метрика | Тип | Смысл | Где |
|---|---|---|---|
| `iam_registrations_total` | Counter | Успешные регистрации | `Register` |
| `iam_logins_total{result}` | Counter | Попытки входа (`success`, `invalid_credentials`, `user_not_found`, `session_error`) | `Login` |
| `iam_logouts_total` | Counter | Успешные выходы | `Logout` |
